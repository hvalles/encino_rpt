<action>
En `encino_rpt/renderers/html.py`, añadir modo clases (TMPL-01):

1. `HtmlRenderer.__init__(self, classes=None, repeat_header=False, *, css=False, template=False, title=None)`. Guardar `self.css`, `self.template`, `self.title`.
2. Helper `_css_decls(style) -> str`: reutiliza la lógica de `_style_attr` pero devuelve las declaraciones `prop:value` separadas por `;` (mismas guardas: `bold`→`font-weight:bold`, `_SAFE_PROP` para claves, `_UNSAFE_VALUE` para valores, `_esc`). No emite ` style="..."`.
3. Helper `_style_block(result) -> str`: si no hay `result.styles`, devuelve `""`; si no, `"<style>" + "".join(f".rpt-cond-{i}{{{_css_decls(r.style)}}}" for i, r in enumerate(result.styles)) + "</style>"`. Solo incluye reglas con declaraciones no vacías.
4. `_cell_attrs(column, value, result)`: si `self.css` es True, devuelve ` class="rpt-cond-1 rpt-cond-3"` (clases de las reglas cuyo `when`/`value` matchean, índices de `result.styles`); si no, mantiene el comportamiento actual (`_style_attr`).
5. `render(result)`: si `self.css`, antepone `_style_block(result)` al `<table>` (y si `self.template`, va dentro del `<head>`). Mantener el path por defecto (`css=False`) byte-idéntico al actual.

Refactor mínimo: extraer la condición de matching de `_cell_attrs` a `_matched_rules(column, value, rules) -> list[int]` reutilizable por ambos modos.
</action>

<action>
Crear `encino_rpt/renderers/markdown.py` (TMPL-03):

1. `class MarkdownRenderer` con `render(self, result) -> str`, consumiendo `walk(result.root)`.
2. Helper `_md_escape(value) -> str`: `str(value).replace("|", "\\|").replace("\n", " ")`.
3. Helper `_md_table(headers, rows) -> str`: tabla GFM
   `| h1 | h2 |` + `|---|---|` + filas `| v1 | v2 |` (celdas con `_md_escape`; `None` → vacío).
4. Helper `_md_cell(value) -> str`: `Link` → `[label](href)` (label fallback a href); `Image` → `![alt](src)` (alt opcional); else `_md_escape(format_value(value, fmt))`.
5. Render:
   - KPIs primero: `**{label}:** {format_value(...)}`.
   - `group_start`: si `node.header`, `{'#' * (depth+2)} {header}` (depth 0 → `##`).
   - `detail`: bufferiza `node.row` en `pending` (lista) por grupo.
   - al salir de detalle (evento `chart`/`pivot`/`group_start`/`group_end`): si `pending`, emitir `_md_table(result.columns, pending)` y limpiar.
   - `group_end`: flush de `pending` primero; luego totales `**{label}:** {value}` indentados (`  ` × depth); footer como texto indentado.
   - `chart`: `**{title or ''}** ({kind}): {label}: v1, v2, …` (misma degradación que TextRenderer).
   - `pivot`: `_md_table([""] + columns, [[row] + cells[i]])`.
   - La indentación de profundidad se aplica a totales/footer, no a los encabezados.
6. `ReportResult.to_markdown(self) -> str` en `encino_rpt/models.py` (import perezoso de `MarkdownRenderer`), docstring Google español con nota de fidelidad.
7. Exportar `MarkdownRenderer` en `encino_rpt/renderers/__init__.py` (añadir a `__all__`).

Sin dependencias nuevas.
</action>
